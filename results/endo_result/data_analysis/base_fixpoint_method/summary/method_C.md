# 方法 C 横跨概念集 A/B/C 的总体总结（仅 size=1）

> 口径说明：以下只汇总 **min_size=1 下的 C-fixpoint**，即单概念角色纯原子。`phi=null` 是 size-1 的自然结果，不再作为问题展开；不讨论 size>1。方法 C 的 `stability` 指**角色一致性** `max(n_center,n_member)/total`，不是位置稳定性。C 集合是“角色纯候选池”，不是重要性排序，也不是 B−C/C/B/底顶判定依据。

---

## 1. 方法 C 在三套概念集上的共同机制

方法 C 在三套 config 下表现出高度一致的“筛选器”性质：

1. **筛的是“角色纯”，不是“最重要”**  
   C 命中不按领域比例出现，而按“在当前压缩事件中是否反复以同一功能角色出现”筛选。  
   - A：保留力学/热力学/数据结构/数据库等具体学科与技术，筛掉牛顿定律/能量守恒/算法/操作系统等 hub。  
   - B：保留 OS 机制、网络协议栈、工程实践，筛掉 algorithms 全域、类型推断/闭包/HTTP/SQL/索引/代码重构等桥接接口。  
   - C：保留数系/代数/拓扑/数论的模块内原子，逻辑与集合论全程 0，极限/序列/闭集/连续映射等基础背景概念不做 C 原子。

2. **输出形态统一：size-1 单概念原子**  
   三套都是单概念 C-fixpoint；`stability` 多数为 1，少数非 1（如 B 的 TCP 0.854、IP 0.915、设计模式 0.84；C 的乘法 0.867、基 0.861、维数 0.955）。  
   非 1 表示角色有翻转/混合，概念卡必须注明“角色一致性高但非绝对纯”。

3. **高频 hub ≠ C 原子**  
   - A：牛顿定律、能量守恒、相对论、量子力学、算法、操作系统、智能体、镜像神经元等 hub 非 C。  
   - B：类型推断、闭包、HTTP协议、SQL、索引、代码重构、操作系统、分页等高频边界/总括概念非 C。  
   - C：逻辑与集合论 20 个概念、序列/极限/连续性/开区间、闭集/连续映射/同调、素数/合数/最大公约数/最小公倍数/同余等基础或桥接概念非 C。  
   这与交接摘要“不动 = 被所有概念调用 = 角色混合”一致：**被调用多不等于角色纯**。

4. **C 层随概念前缀/事件空间大幅重组**  
   - A：51→71→91 有约 16 个跨尺度稳定核心（physics 具体学科 + cs 具体技术），111 事件数骤降导致坍缩到 11。  
   - B：C 集合非单调累积；languages 先高后零，AI 部分前缀 4/9 全量后 0/20，systems 稳定 11 但成员重排，networks 到 C-111 覆盖 9/10。  
   - C：51 代数+数系+分析前段，71 分析退出、几何小模块，91 代数+数系双主，111 拓扑/数论成批进入、代数收缩；Jaccard 51→71≈0.24，91→111≈0.23。  
   因此 C 原子必须绑定 `config_method + scale`，不能跨 scale 直接套用。

5. **support 不能跨 scale 直接比，高 support ≠ 角色纯**  
   - A：support 排名跨尺度剧烈重排（运动学 0.514→0.186；热力学 0.426→0.079）；111 的 support 基数与 51/71/91 不可比。  
   - B：n_events 423/529/392/247 差异大，C-111 support 最高 0.401 但 count 反而不高于 C-91；count/排名比 support 更可靠。  
   - C：91 乘法 support 最高但 stability 最低 0.867；71 有理数 support 最高 stability 0.879；51 线性映射 support 最高 stability 0.952。  
   结论：**高支持度只说明当前事件空间中常出现，不说明功能单一**。

6. **低 support + 高 logic 是局部紧密小核心，不是全局桥接**  
   - A：111 的 `变换` support 0.060、sources 8 条，证据薄，概念卡需谨慎。  
   - B：C-111 出现 boundary=2 的小节点（版本控制、单元测试、敏捷开发、套接字、需求分析），局部角色纯但结构边缘。  
   - C：111 的线性组合/维数/线性无关、开集等 support 低、energy 低，但 logic 0.95–1.0，是模块内紧密小核心。  
   不能把“低 support 高 logic”误读为跨模块桥接或全局基础。

## 3. 三套概念集的差异画像

### 3.1 A：跨领域下，C 是“具体学科/技术实体检测器”

- C 保留 physics 的力学/热力学/电磁学/统计力学/宇宙学等具体学科，筛掉牛顿定律/能量守恒/相对论/量子力学等框架 hub。
- cs 保留数据结构/数据库/网络/软件工程/机器学习等具体技术，筛掉算法/操作系统通用层。
- ai 保留有明确输入-输出功能的模型（深度学习/迁移学习/专家系统/数据挖掘/注意力机制等），筛掉强化学习/GAN/知识图谱等训练/表示框架；`智能体` 在 91 退出但仍是 hub。
- cognitive_science 对概念集规模高度敏感，71→91 换血，仅元认知/具身认知跨尺度保留。
- neuroscience 是“晚出现、强保留”域：91 六个、111 八个，是 111 唯一扩展域；神经元-突触-递质-脑电图-fMRI 天然高 logic 小 clique。
- principles 在 111 选择性进入：抽象/迭代/变换进入，优化未进；`变换` 证据薄（support 0.060），概念卡需谨慎。
- **A 的核心结论**：C 抓“可被结构化定义的角色纯具体单元”，适合写概念卡；hub 概念需单独处理；math 在 config_A 下不适用 C，需 config_C；111 事件骤降，不能证明“神经科学比物理/CS 更本质”。

### 3.2 B：CS 单领域下，C 是“模块化功能专才/基础设施检测器”

- algorithms 四个 scale 全 0：排序/查找/动态规划/贪心/分治/递归/迭代是跨模块通用方法，角色混合，不是 C 专才原子。这不等于算法无意义，只表示不是 C 口径下的单概念角色纯。
- languages 12/15→11/15→0→0：早期语言前端（词法/语法/语义/类型/语法树）角色纯，网络/数据库/AI/SWE 加入后整体退出。
- systems 最稳定：约 11 个，但成员重排；C-111 中操作系统/分页退出，调度算法/中断进入；进程/线程/并发 count 大幅下降。C 偏好“机制型专才”（虚拟内存、死锁、缓存、中断、系统调用、调度算法），而非总括概念。
- networks 从 2/9→5/10→9/10：C-111 几乎覆盖协议栈，前五全是网络概念；HTTP 是唯一非 C 网络边界，偏应用层接口/桥接。
- databases 部分进入：关系数据库/事务/NoSQL/范式/分布式数据库；SQL/索引常为高频非 C 边界，偏接口/操作层。
- AI 只在 C-91 部分前缀 4/9，C-111 全量 0/20：完整 AI 块加入后内部概念互相竞争边界，单概念角色纯性消失。
- SWE C-111 首次 6/9：版本控制/设计模式/单元测试/敏捷开发/集成测试/需求分析；代码重构是高频非 C 边界。
- **B 的核心结论**：C 近似“职责边界清晰的模块清单”，最大前缀下偏向网络协议栈/OS 机制/工程实践的基础设施化概念；领域块顺序和 n_events 变化共同造成序列，不能当纯规模轨迹。

### 3.3 C：数学单领域下，C 是“模块内专才原子层”

- C 层不是数学层级本身：51 分析前段可成 C，71 完整分析加入后分析几乎全退出；91 完整几何加入后几何仅欧氏空间留下；111 拓扑/数论成批进入、代数收缩为小核心。
- 逻辑与集合论 20 个概念在四个 scale 中 0 个 C 原子：基础公理/背景约束在 C 视角下不是角色纯单元素，更常作为邻居/边界。
- 数系是最稳定模块：乘法/有理数/整数/序反复出现；代数随 scale 换血；分析仅 51 阶段；几何 71/91 少量；拓扑/数论 111 成批。
- 模块化强、跨模块边弱：C 原子的 boundary 基本只列同模块邻居，跨模块边很弱；C 层是“模块内结构主义”，不是全局统一结构。
- 高 support ≠ 角色纯：91 乘法 support 最高但 stability 最低；71 有理数、51 线性映射同理。
- 低 support 高 logic 的局部小核心（111 线性组合/维数/线性无关、开集）是模块内紧密原子，不是全局桥接。
- **C 的核心结论**：C 层是“当前概念前缀内的局部专才型原子层”，适合做绑定 scale 的模块内术语卡，不适合做全局公理卡或跨模块桥接骨架。

## 4. 方法 C 到底“抓到了什么、没抓到什么”

### 抓到了
- **角色纯的单概念功能原子**：具体学科/技术实体、OS 机制、网络协议栈、工程实践、数学模块内原子、神经科学实体-关系-测量簇。
- **局部模块核心**：在各自模块内 boundary 集中、logic 分层合理、energy 与 logic 同向的单元。
- **可被结构化定义的概念卡候选**：有明确外延/功能边界/强逻辑邻居，可追溯到 `core/boundary/logic/energy/stability/support/count/method=C/domain/meta`。
- **范围敏感的本质候选**：跨尺度持续项可做稳定卡；阶段项可做版本卡；非 1 stability 项标注“角色一致性高但非绝对纯”。

### 没抓到/不能用来判定
- **不是“最重要概念”排序**：hub、通用方法、总括概念、桥接接口常被过滤。
- **不是“基础公理层”**：A 的 math 0、C 的逻辑/集合论 0、B 的 algorithms 0 都说明 C 层不覆盖基础/通用层。
- **不是“跨模块桥接骨架”**：三套 C 层都模块化强、跨模块边弱；低 support 高 logic 是局部紧密，不是全局桥接。
- **不能单 C 判 B−C/C/B/底顶中间**：需要 B 的 Lattice 下界/上界信息；当前只能给“角色纯候选池”。
- **不能跨 scale 比 support 当重要性**：必须绑定 scale 和 n_events；count/排名更稳。
- **不能把 111/A 的坍缩或 B 的前缀效应当纯结构本质**：A-111 n_events 骤降；B 是领域块加入顺序；C 是数学层级前缀。

## 6. 禁忌与易错点汇总

1. **不要把 C 当“最重要概念”排序**：C 是角色纯筛选器，不是中心性/基础性检测器。
2. **不要把高 support 等同于角色纯**：A/B/C 都有高 support 但 stability 非 1 或 hub 非 C 的反例。
3. **不要跨 scale 直接比 support**：必须结合 n_events；A-111 骤降、B 四组事件数差异大。
4. **不要把 C 层当公理层/全局桥接骨架**：A math 0、B algorithms 0、C 逻辑集合论 0；低 support 高 logic 是局部小核心。
5. **不要用单 C 判 B−C/C/B/底顶中间**：需要 B 方法 Lattice 信息。
6. **不要把 A-111 坍缩当“神经科学更本质”**：n_events 897→133，只能作事件稀疏下 C 行为案例。
7. **不要忽略 B 的领域块顺序和 C 的数学层级前缀**：序列不是纯规模轨迹。
8. **不要忽略 stability 非 1、boundary 强邻居子集、外部锚定不对称**：概念卡必须标注限定。
9. **不要把“不动”一律当“角色纯”**：A/B/C 都显示被大量引用的 hub 往往角色混合；C 原子是“局部语境中的角色纯”。

## 7. 一句话总结

**横跨 A/B/C 三套概念集，方法 C 在 size=1 下稳定地表现为“角色纯单概念原子检测器”：它抓的是局部模块内功能单一、职责边界清晰、可被结构化定义的专才型原子，而不是全局最重要概念、基础公理层或跨模块桥接骨架。A 偏具体学科/技术实体并筛掉框架 hub，B 偏 OS 机制/网络协议栈/工程实践并筛掉 algorithms 与桥接接口，C 偏数学模块内专才并筛掉逻辑集合论与基础背景概念；三者共同呈现“命中不均、hub 过滤、前缀敏感、稳定核心有限、高 support≠角色纯、C 层随 scale 重组”的模式。工程上应把 C 集合当作绑定 `config_method+scale` 的概念卡候选池，分层建稳定卡/版本卡/桥接卡/进阶卡，并严格标注证据与限定，不单 C 做 B−C/C/B/底顶判定。**


# 方法 C 的理论总结：它测的不是“重要性”，而是“可定义性”

> 口径：只谈 min_size=1 的 C-fixpoint，即单概念角色纯原子。不讨论 size>1，不讨论 B−C/C/B/底顶判定（那些需要 B 方法）。以下不做工程清单，做的是**事后解释、意义赋予、与现实方法/哲学立场的对照**。

---

## 一、先把 C 方法在理论上重新定位：它测的是一个“关系属性”，不是“内在属性”

三套概念集（A 跨领域 / B CS / C 数学）跑下来，C 的 output 有一个跨数据集不变的性质：**它从不按“领域比例”或“概念重要性”出牌**。A 里 math 全程 0、B 里 algorithms 全程 0、C 里逻辑与集合论全程 0——这三组“零”不是巧合，它们恰好是各自概念集里**最基础、被调用最多、最像“公理/通用语言”**的部分。

这就逼出一个理论结论：

> **C 方法测的不是“这个概念重不重要”，而是“这个概念在当前压缩事件里，能不能被收敛成一个功能单一的角色”。**

换句话说，C 测的是**“可定义性”（definability）**——一个概念能不能被写成一张“内涵 + 外延 + 为什么能压缩”的卡。hub 概念（牛顿定律、算法、逻辑连接词）不是不重要，而是**它们被所有概念调用，角色必然发散，因而不可被单义定义**。C 把“可定义”和“重要”这两件事拆开了。

这个拆分的理论意义很大：它意味着**“基础性”与“可定义性”是两个正交维度**。一个概念可以很基础但不可定义（逻辑连接词、集合），也可以很具体但可定义（神经可塑性、虚拟内存、矩阵）。C 方法只抓后者。这不是 C 的缺陷，是 C 的**测量对象本身**——它测的就是“语境收敛度”，而收敛度天然与“被调用广度”负相关。

---

## 二、事后解释：为什么三套概念集给出三种不同的 C 画像

### 2.1 A（跨领域）：C 收敛于“有明确对象与相互作用的具体实体”

A 的 C 保留力学/热力学/电磁学/数据结构/数据库/神经网络/迁移学习/专家系统，筛掉牛顿定律/能量守恒/相对论/算法/操作系统/强化学习/GAN/知识图谱。这个模式可以这样解释：

**跨领域语境下，一个概念要维持“角色一致”，必须有一个明确的“对象 + 作用”结构。**“力学”有明确对象（物体运动）和明确作用（受力），它在任何领域被调用时都是“研究物体受力的学科”这个角色；“牛顿定律”则是被所有物理子领域调用的**框架**，它出现在力学里是定律、出现在宇宙学里是工具、出现在工程里是约束——角色必然发散。

同理，“数据结构”有明确对象（数据组织方式），“算法”是被所有 CS 子领域调用的**方法框架**；“深度学习”有明确输入-输出功能，“强化学习”是训练范式，被策略学习、机器人、博弈多处调用，角色发散。

**理论解释**：C 在 A 上测到的是“**领域内可命名的专才**”。跨领域概念集里，能保持角色纯的，是那些“在某个领域内有明确职责边界”的实体；被多领域共享的框架，注定角色混合。这与交接摘要“不动 = 被所有概念调用 = 角色混合”完全吻合，而且给出了**跨领域的直接证据**。

### 2.2 B（CS）：C 收敛于“模块化功能单元”，本质是“职责边界清晰度检测器”

B 的 C 画像最“工程化”，但事后看它测的其实是一个很纯的理论量：**模块化程度**。

- OS 机制（虚拟内存、调度、中断、死锁、缓存、系统调用）稳定进入 C——它们每个都有明确职责，是 OS 分层设计里的“功能单元”。
- 网络协议栈到 C-111 覆盖 9/10——协议栈本身就是“分层 + 每层职责单一”的典范。
- algorithms 全 0——排序/查找/动态规划/贪心/分治/递归/迭代是**跨模块的通用方法**，它们在 OS 里是调度算法、在数据库里是查询优化、在网络里是路由算法，角色必然混合。
- 类型推断/闭包/HTTP/SQL/索引/代码重构是高频非 C——它们是**接口/桥接**，被大量模块调用，职责不单一。
- 操作系统/分页在 C-111 退出——总括性概念在概念集变大后角色混合，被机制概念取代。

**理论解释**：CS 的本质是“分层 + 模块化”，所以 C 在 B 上自然收敛成“**模块化功能专才检测器**”。它测的“角色纯”，翻译成工程语言就是“高内聚、低耦合、职责单一”。B 的 C 结果之所以看起来像“模块清单”，是因为 **CS 这个概念集本身就把“模块化”写进了它的本体结构**——C 只是把这个结构显影出来。

### 2.3 C（数学）：C 收敛于“模块内专才原子”，暴露的是“数学的层级不是公理层级”

C 的结果最有理论冲击力：**逻辑与集合论 20 个概念在四个 scale 中 0 个 C 原子**；分析在 51 出现、71 退出；几何只在 71/91 少量；111 拓扑/数论成批进入、代数收缩。

这不是“C 不喜欢数学基础”，而是：

**数学的“基础概念”（集合、函数、极限、逻辑连接词）恰恰是被所有数学分支调用的“背景语言”，角色必然混合；而 C 抓到的是“当前层级内的专才术语”**——数系的乘法/有理数/整数/序、代数的矩阵/环/群、拓扑的连通/紧致/同胚、数论的整除/模运算/费马小定理。这些是“在当前层级内功能单一、可被单独定义”的原子。

**理论解释**：C 在 C 上测到的是“**范围敏感的模块内专才**”。它同时暴露了一件事：**数学的层级（数系→代数→分析→几何→拓扑）是“概念加入顺序”，不是“C 的收敛顺序”**。分析在 51 能成 C，完整分析加入后反而退出；代数在 91 扩张、111 收缩。这说明“角色纯”不是数学层级的固有属性，而是“当前概念集合的共现结构”的函数。

这个结论对“数学基础主义”是一个温和的反驳：**如果“基础”意味着“被所有概念调用”，那么基础概念恰恰是 C 抓不到的**——它们不可被写成角色纯的定义卡，只能作为背景约束存在。

## 三、C 方法映照到现实生活中的具体方法（重点）

这是你特别问的。C 方法不是凭空造出来的测量，它在现实中有多个“同构”的方法论传统。下面按贴合度排序。

### 3.1 最贴合：术语学中的“术语识别”（terminology extraction）

术语学（terminology science, ISO 704 传统）的核心问题就是：**一个学科里，哪些词能成为“术语”（term），哪些只是“普通词”（word）？** 判据是：术语必须有**单一指称、明确内涵、在学科内功能稳定**；普通词多义、语境依赖、跨领域通用。

C 方法做的正是这件事的自动化版本：

- C-fixpoint = 可被写成“术语卡”的候选（内涵/外延/为什么能压缩）。
- hub 非 C = 普通词/背景词（算法、逻辑连接词、集合），多义、语境依赖。
- 跨 scale 重组 = 术语的“范围敏感性”——同一个词在不同学科范围里，术语地位不同。

**现实对应**：编词典、建本体、做术语标准化时，第一步就是“区分术语与普通词”。C 方法给出的是一个**可计算、可追溯的术语候选池**，而且它的“筛掉 hub”恰好对应术语学的核心直觉：**被所有子领域借用的词，往往不是术语，是通用语言**。

### 3.2 认知科学：专家知识的“组块化”（chunking）

认知心理学里，专家与新手的关键差别是：专家把大量信息压缩成“组块”（chunk）——一个组块功能单一、可被整体调用、有明确边界。C-fixpoint 就是**概念层面的组块**：它在压缩事件里反复以同一角色出现，因而能被“整体调用”。

hub 概念对应的是**未被组块化的背景知识**——新手知道“算法”这个词，但不知道它在具体场景里怎么用；专家知道“虚拟内存”是一个可整体调用的功能单元。C 方法测到的“角色纯”，翻译成认知语言就是“**这个单元是否已经被组块化到可单义调用**”。

**现实对应**：教学设计里，“先教什么”不是按“基础→高级”，而是按“哪些单元已经被组块化到可被单独命名”。C 的稳定核心（A 的 16 个、B 的 systems/网络、C 的数系）就是“可先建卡的组块”。

### 3.3 分类学：模式标本（type specimen）

生物分类学里，一个物种有一个“模式标本”作为定义锚点——它不是“最重要的个体”，而是“最能代表该物种鉴别特征的个体”。C-fixpoint 很像**概念的模式标本**：它不是最高 support 的概念（A 的 111 里 fMRI support 0.805 最高，但 C 抓的是神经可塑性等），而是**最能代表“这个角色”的单元**。

**现实对应**：建知识库时，每个概念需要一个“锚点定义”。C 给出的就是“哪些概念适合做锚点”——角色纯、边界清晰、可追溯。hub 不适合做锚点，因为它们代表不了单一角色。

### 3.4 波兰尼的“默会知识”：hub 是不可言说的背景

波兰尼（Michael Polanyi）说“我们知道的比我们能说出来的多”（tacit knowledge）。C 结果给了一个精确的对应：**hub 概念就是“不可言说的背景”**——算法、逻辑连接词、集合、牛顿定律，它们被所有概念调用，但正因如此，**它们不能被写成角色纯的定义**。你能用“算法”做很多事，但你很难给“算法”写一张单义的内涵卡，因为它在你用的每个场景里扮演不同角色。

C 方法测到的“可定义性”，本质上是**“可言说性”（articulability）**：只有角色纯的概念才能被“说出来”（写成卡）；角色混合的 hub 只能作为背景“被使用”，不能被单独“被定义”。

**现实对应**：专家系统/知识获取的经典难题——专家能做事，但说不出“怎么做”。C 方法给了一个结构性的解释：**专家用的很多概念是 hub，角色混合，天然不可言说**；能被言说的，是那些已经被组块化到角色纯的专才单元。

### 3.5 维特根斯坦的“家族相似”与“语言游戏”

维特根斯坦后期哲学的核心是：很多概念没有“本质”，只有“家族相似”；一个词的意义由它在“语言游戏”中的用法决定。C 结果给了一个**可操作的版本**：

- C-fixpoint = 在**当前语言游戏**中用法收敛的概念（角色纯）。
- hub 非 C = 在**多个语言游戏**中被使用、用法发散的概念（家族相似）。
- 跨 scale 重组 = 换一个“语言游戏”（概念集），收敛性就变。

**理论对应**：C 方法测的“角色纯”不是柏拉图式的本质，而是**“在当前语言游戏中的用法一致性”**。这正好对应交接摘要“C/B 是范围敏感的本质候选，不是绝对本质”的定位。维特根斯坦会说：C 抓到的不是“本质”，是“当前游戏里规则最清楚的棋子”。

### 3.6 科学哲学：理论术语 vs 观察术语 / 背景语言

科学哲学里有一个经典区分：**理论术语**（有明确理论定义）vs **观察术语/背景语言**（被理论使用但不被理论定义）。C 结果精确对应：

- C-fixpoint = 理论术语（在当前理论中有明确角色）。
- hub 非 C = 背景语言/观察术语（被所有理论使用，但自身不被定义）。
- 逻辑与集合论在 C 中 0 = 它们是**元语言**，不是对象语言里的术语。

**现实对应**：写教科书时，哪些词需要进“术语表”，哪些词默认读者已懂、不进术语表？C 方法给出的是一个**结构性的判据**：进术语表的，是角色纯的专才；不进术语表的，是被所有章节调用的背景词。

## 四、C 结果的哲学意义：它测到了一个“本体论量”

把上面的现实对应收拢，C 方法测到的本体论量可以这样表述：

> **C = 一个概念集里，“在当前压缩事件中功能收敛、可被单义定义”的单元占比。**

这不是“重要性”，不是“基础性”，而是**“可定义性 / 语境收敛度 / 可言说性”**。它直接对应几组哲学对立：

| 哲学对立 | C 的对应 |
|---|---|
| 本质主义 vs 关系主义 | C-fixpoint 偏“本质主义候选”（角色纯）；hub 偏“关系主义”（角色由多语境关系定义）。但 C 的“本质”是**范围敏感的本质**，不是绝对本质。 |
| 结构主义 | C 在数学上表现为“模块内结构主义”——意义由模块内邻居位置定义；跨模块边弱，不是全局结构。 |
| 功能主义 | C 在 CS 上表现为“功能主义”——意义由职责/接口/模块功能定义。 |
| 可言说 vs 默会 | C-fixpoint 可言说（可写卡）；hub 默会（背景使用）。 |
| 理论术语 vs 背景语言 | C-fixpoint 是理论术语；hub 是背景语言/元语言。 |

**最重要的一条哲学结论**：三套概念集的 C 画像不同（A 关系主义候选 / B 功能主义候选 / C 模块内结构主义候选），**这不是 C 方法的偏差，而是三套概念集的本体结构不同**。C 只是把每种概念集“哪种意义观占主导”显影出来。A 是跨领域拼接，所以关系主义占主导；B 是分层模块化，所以功能主义占主导；C 是内生的数学层级，所以模块内结构主义占主导。**C 方法是一面镜子，照出的是概念集自己的本体论。**

## 五、C 方法的理论边界：它不能做什么，以及为什么这恰恰是“抓重点”的认知论价值

### 5.1 C 不能做的

- 不能判“重要性/基础性”：hub 被筛掉，但 hub 恰恰是最基础的。
- 不能判“底/顶/中间元素”：那需要 B 的 Lattice 下界/上界。
- 不能算 C/B：那需要 B 做对照，测“专才 vs 通用”的分工结构。
- 不能跨 scale 比 support：support 是事件空间的函数，不是概念属性。

### 5.2 但“抓重点”的认知论价值恰恰在这里

交接摘要说本项目是“抓重点”，不是“概念生成”。C 方法给“抓重点”一个精确的认知论解释：

> **“抓重点”不是“抓最重要的”，而是“抓当前语境中功能收敛、可被单义命名的单元”。**

这是人类认知的一个基本机制：面对海量信息，我们不是先找“最重要”的，而是先找“**能被命名、能被单独调用、能被写成定义**”的单元——因为只有这些单元才能进入工作记忆、被交流、被建卡。hub 概念虽然基础，但它们不可被单义命名，只能作为背景“被使用”，不能被“被定义”。

所以 C 方法的理论定位是：**它是“可言说性/可定义性”的检测器，是“抓重点”这一认知操作的自动化版本**。它抓到的不是“知识的核心”，而是“知识里能被写成术语卡的那一层”。这一层恰好是概念卡工程、术语标准化、教学设计、本体建库的**第一层可操作对象**。

## 六、一句话总结（理论版）

**方法 C 在 size=1 下测的不是“概念重要性”，而是“概念在当前压缩事件中的角色收敛度/可定义性/可言说性”——它把“基础性”与“可定义性”拆成两个正交维度，抓后者、放前者。三套概念集的 C 画像不同（A 具体学科/技术实体的关系主义候选、B 模块化功能单元的功能主义候选、C 模块内专才原子的结构主义候选），不是 C 的偏差，而是三套概念集本体结构的显影：C 是一面照出“哪种意义观占主导”的镜子。它在现实中同构于术语学的术语识别、认知科学的组块化、分类学的模式标本、波兰尼的默会知识边界、维特根斯坦的语言游戏收敛、科学哲学的理论术语/背景语言之分。它的理论边界（不能判重要性/底顶/C/B）恰恰定义了“抓重点”的认知论价值：抓重点不是抓最重要的，是抓**能被单义命名、能被写成定义卡**的那一层——hub 被筛掉，正因为它们是“不可言说的背景”，而这正是 C 方法最深刻的理论洞见。**
