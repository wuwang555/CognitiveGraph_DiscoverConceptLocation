# 概念结构、实际意义

## 1. 先明确 config_B 的“前缀”实际包含什么

config_B 的 `CORE_CONCEPT_DEFINITIONS_B` 是按领域块顺序定义的：  
**algorithms(22) → theory(10) → languages(15) → systems(15) → networks(10) → databases(10) → ai(20) → software_engineering(10) → security(8)**。

因此 51/71/91/111 不是均匀采样，而是**按领域块逐步加入概念**：

| scale | 实际包含的领域块 | 尚未包含 |
|---|---|---|
| 51 | algorithms 全部22 + theory 全部10 + languages 全部15 + systems 前4（操作系统、进程、线程、并发） | networks、databases、AI、SWE、security |
| 71 | 上述 + systems 剩余11 + networks 前9（不含一致性协议） | databases、AI、SWE、security；networks 缺一致性协议 |
| 91 | 上述 + networks 第10 + databases 全部10 + AI 前9 | SWE、security；AI 缺后11个 |
| 111 | 上述 + AI 剩余11 + SWE 前9（不含持续集成） | security；SWE 缺持续集成 |

**这一点非常关键**：四个 scale 的 C 结果变化，不能简单理解为“规模增大导致结构演化”，其中很大一部分是**领域块加入顺序**造成的。也就是说，C-51 的语言前端主导、C-71 的网络/系统进入、C-91 的数据库/AI 进入、C-111 的 SWE 进入，都带有明显的前缀结构效应。

## 2. C 方法输出的总体形态

四组 C 结果有高度一致的形态：

1. **全部是 size-1 单概念 fixpoint**，`phi` 全为 `null`。
2. `stability` 绝大多数为 `1.0`；只有少数低于 1：
   - C-71：分布式系统 0.993；
   - C-111：TCP协议 0.854、IP协议 0.915、设计模式 0.84。
3. 因此 C 方法在这四组数据中提取的是**“角色纯的单概念原子”**，不是复合概念群。
4. 由于只有 C 方法结果，当前不能判断这些单概念在 B 方法中是否也作为最小频繁项集出现，也不能判断它们是否属于 B−C 的“角色混合”部分。
5. `edge_weights.csv` 可见行中 `weight_multichannel` 与 `weight_high_order` 完全相同，说明记录层面高阶项尚未产生差异化边权。

## 3. 四锚点的领域组成与“命中率”

把每个 scale 的 C fixpoint 数量除以该 scale 前缀内该领域概念数，可以得到一个很有用的观察：**C 方法并不是按领域比例选概念，而是按角色纯筛选**。

| 领域 | C-51 | C-71 | C-91 | C-111 |
|---|---:|---:|---:|---:|
| algorithms | 0/22 | 0/22 | 0/22 | 0/22 |
| theory | 6/10 | 7/10 | 1/10 | 0/10 |
| languages | 12/15 | 11/15 | 0/15 | 0/15 |
| systems | 4/4 | 11/15 | 11/15 | 11/15 |
| networks | 未包含 | 2/9 | 5/10 | 9/10 |
| databases | 未包含 | 未包含 | 4/10 | 3/10 |
| ai | 未包含 | 未包含 | 4/9 | 0/20 |
| software_engineering | 未包含 | 未包含 | 未包含 | 6/9 |

几个强信号：

- **algorithms 在四个 scale 中全部为 0**，尽管它是最早加入、数量最大的领域块（22 个）。  
  这说明在当前事件结构和 C 角色纯筛选下，算法类概念没有形成单概念角色纯 fixpoint。它们更可能是“通用方法/桥接角色”，而不是局部功能专才。注意：**未被 C 选中不等于无意义**，只表示当前不是角色纯单概念原子。
- **languages 从 12/15 → 11/15 → 0 → 0**：早期语言/编译前端角色纯度高，但随着 networks、databases、AI、SWE 加入，语言簇整体退出 C。  
  这不是说语言概念消失，而是说在更大的概念集和事件结构下，它们不再表现为角色纯单概念。
- **systems 是最稳定的领域**：4/4 → 11/15 → 11/15 → 11/15。数量始终较高，但成员和支持度在 C-111 发生重排。
- **networks 从 2/9 → 5/10 → 9/10**：随着网络块逐步完整加入，C 对网络协议栈的覆盖迅速上升；到 C-111 几乎整个网络块都进入 C，只剩 `HTTP协议` 未进入。
- **AI 只在 C-91 出现 4/9，C-111 全量 AI 加入后反而 0/20**。这是“领域块加入改变事件结构”的典型信号：AI 概念在部分加入时角色纯，在完整加入后被其他 AI 概念和外部边界稀释/混合。
- **SWE 在 C-111 首次出现即 6/9**，形成小簇，说明工程实践类概念在当前事件结构下具有较好的局部角色纯性。

## 4. 四锚点的结构序列

### 4.1 领域重心迁移

| scale | 主导领域 | 头部概念（按 count） |
|---|---|---|
| C-51 | languages + theory + systems 前4 | 解释器168、类型系统156、语法树147、词法分析137 |
| C-71 | systems 扩张 + networks 进入 | 套接字178、分布式系统143、虚拟内存122、操作系统98 |
| C-91 | systems + networks + AI + databases 多簇 | 虚拟内存100、进程92、线程89、网络拓扑/计算机网络88 |
| C-111 | networks + systems + SWE | 数据包99、TCP协议89、分布式系统82、IP协议82 |

**结构序列**：  
语言前端主导 → 网络/系统主导 → 系统/网络/AI/数据库多簇 → 网络/系统/软件工程主导。  
语言、理论、AI 在 C-111 全部退出；algorithms 始终缺席。

### 4.2 四锚点交集只有 3 个

C-51、C-71、C-91、C-111 的四方交集：

| 概念 | 领域 |
|---|---|
| 线程 | systems |
| 进程 | systems |
| 并发 | systems |

也就是说，跨四个前缀最稳定的 C 单元只剩 systems 的线程、进程、并发。  
但即使这三个，C-111 的 count 也大幅下降：进程 92→18，线程 89→15，并发 56→47。  
这说明“稳定进入 C”不等于“支持度稳定”，后者受事件数和概念集扩张强烈影响。

### 4.3 C-91 → C-111 的成员重排最剧烈

C-111 保留 C-91 的 15 个，消失 10 个，新增 14 个。  
消失的包括：神经网络、机器学习、无监督学习、反向传播、分布式数据库、数据库范式、分页、操作系统、可计算性、SQL。  
新增的包括：TCP协议、IP协议、路由、分布式系统、调度算法、中断、版本控制、设计模式、单元测试、敏捷开发、集成测试、NoSQL、事务、需求分析。

这说明在 config_B 的领域块顺序下，**C 集合不是单调累积的**；新领域加入会重排旧领域的角色纯性。

## 5. 局部簇的实际意义

### 5.1 语言/编译簇：早期“前端专才”，后期整体退出

C-51/C-71 中语言簇包含解释器、类型系统、语法树、词法分析、编译器、语法分析、语义分析、多态、函数式编程等。  
但高频边界枢纽 `类型推断`、`闭包` 在 C-51/C-71 一直未被 C 选中。  
实际意义：C 方法偏向“前端流程中的功能专才”，而 `类型推断/闭包` 更像被多个概念引用的桥接/接口概念，角色混合。

到 C-91/C-111，语言簇整体退出 C。  
这不一定说明语言概念不再重要，而是说明在更大的概念集和事件结构下，它们不再表现为角色纯单概念。当前不能判断是“角色混合化”还是事件结构变化，需要 B 方法对照。

### 5.2 计算理论簇：早期稳定，后期收缩到 0

C-51/C-71 中理论簇有 6–7 个，C-91 只剩 `可计算性`，C-111 为 0。  
早期理论簇内部 logic 很强（形式语言、图灵机、自动机、可计算性等），但 support 总体低于语言前端。  
实际意义：理论概念在较小前缀中可作为角色纯原子，但随着数据库/AI/SWE 加入，它们不再占据 C 的单概念原子位置。`有限状态机`、`正则表达式`、`上下文无关文法` 等有时作为高频边界但非 C，提示它们可能是桥接角色。

### 5.3 系统/OS 簇：最稳定的 C 领域，但成员重排

systems 是唯一在四个 scale 中都保持 11 个左右 C fixpoint 的领域。  
但成员变化明显：

- C-51：操作系统、进程、线程、并发（仅前4个 systems 概念）。
- C-71/C-91：虚拟内存、操作系统、并发、线程、并行、死锁、分页、进程、缓存、内存管理、系统调用。
- C-111：调度算法、死锁、虚拟内存、并发、中断、内存管理、缓存、进程、线程、系统调用、并行；操作系统、分页退出。

高频非 C 边界在 C-91 是 `调度算法`、`中断`；到 C-111 它们进入 C，而 `操作系统`、`分页` 退出。  
实际意义：C 方法在 systems 中捕捉的是“机制型专才”（调度、死锁、虚拟内存、并发、缓存、中断、系统调用），而 `操作系统` 这种总括性概念在更大概念集中更容易角色混合，不再是角色纯原子。

### 5.4 网络簇：从边缘到头部，C-111 几乎覆盖整个协议栈

networks 的 C 命中率：2/9 → 5/10 → 9/10。  
C-111 中网络簇包含数据包、TCP、分布式系统、IP、路由、计算机网络、一致性协议、网络拓扑、套接字，仅 `HTTP协议` 未进入 C。  
实际意义：网络协议栈在 config_B 中表现出很强的局部角色纯性，尤其是数据包、TCP/IP、路由、分布式系统等。  
`HTTP协议` 作为高频边界但非 C，提示它更偏应用层接口/桥接角色，而不是当前事件结构下的角色纯原子。

### 5.5 数据库簇：部分进入，SQL/索引常作为非 C 边界

C-91 数据库簇：分布式数据库、数据库范式、关系数据库、SQL（4/10）。  
C-111 数据库簇：关系数据库、NoSQL、事务（3/10）。  
`SQL`、`索引` 在 C-111 是高频非 C 边界。  
实际意义：数据库领域的 C 原子集中在“关系模型/事务/范式/分布式”这些局部功能单元；`SQL`、`索引` 更像接口/操作层概念，角色混合度较高。

### 5.6 AI 簇：只在部分加入时出现，完整加入后退出

C-91 中 AI 有 4/9：神经网络、机器学习、无监督学习、反向传播。  
C-111 中 AI 全量加入后为 0/20。  
实际意义：AI 概念在部分前缀下可形成角色纯原子，但在完整 AI 块加入后，内部概念（监督/无监督/强化/深度学习/CNN/RNN/Transformer 等）相互竞争边界，导致没有单概念达到 C 的角色纯标准。  
这并不意味着 AI 概念无结构，而是说它们在当前 C 口径下不是“单概念角色纯原子”。

### 5.7 软件工程簇：C-111 首次出现即 6/9

C-111 中 SWE 包含版本控制、设计模式、单元测试、敏捷开发、集成测试、需求分析；`代码重构`、`软件设计`、`软件工程` 未进入 C。  
实际意义：工程实践类概念在当前事件结构下具有较好的局部角色纯性，尤其是测试/版本/设计模式/敏捷开发这一组。`代码重构` 作为高频非 C 边界，提示它更偏跨实践桥接角色。

### 5.8 algorithms：四个 scale 全部缺席

algorithms 是最早加入、数量最大的领域块，但 C-51/71/91/111 中均为 0。  
这可能与算法概念的“通用方法”性质有关：排序、查找、动态规划、贪心、分治、递归、迭代等往往作为跨领域方法被调用，角色混合度高，不容易成为角色纯单概念。  
但必须强调：**这是 C 方法下的观察，不等于算法概念无意义或不是 fixpoint；只是它们不是当前 C 口径下的角色纯单概念。**

## 6. 支持度、边界度与头部集中度

### 6.1 support 不能跨 scale 直接比

四组 n_events 分别为 423、529、392、247，差异很大。  
C-111 的 support 最高值 0.401 高于 C-91 的 0.255，但最大 count 反而从 100 降到 99。  
因此跨 scale 比较时，**count 和排名比 support 更可靠**。

Top4 占总 count 比例：

| scale | Top4 占比 |
|---|---:|

头部集中度没有单调趋势，但头部领域从语言前端 → 网络/系统 → 系统/网络 → 网络簇。  
C-111 前五全是 networks，说明在最大前缀下网络协议栈是 C 方法最突出的角色纯区域。

### 6.3 边界度越来越稀疏

这说明 C-111 的 C 集合既有高耦合的系统/网络核心，也有边界很窄的工程实践小原子。

## 7. 综合分析：C 方法在 config_B 下到底抓到了什么

可以把四组 C 结果概括为：

> **C 方法在 config_B 下抓到的不是“CS 概念全集”，而是当前概念集和事件结构下的“角色纯功能原子”。这些原子强烈依赖于领域块的加入顺序；它们不是按领域比例均匀出现，也不是单调累积的。**

具体特点：

1. **C 集合不是领域抽样，而是角色纯筛选**  
   algorithms 全缺席、languages 先高后零、AI 只在部分前缀出现，都说明 C 不是“每个领域选代表”，而是按角色一致性筛选。

2. **C 偏爱局部功能专才，过滤通用/桥接概念**  
   例如语言簇中 `类型推断`、`闭包` 常为高频非 C；systems 中 `调度算法`、`中断` 在 C-91 是非 C，到 C-111 才进入；networks 中 `HTTP协议` 在 C-111 是唯一非 C 网络边界；数据库 `SQL`、`索引` 也是非 C 边界。  
   这些高频边界节点是后续 B 方法对照的重点候选，但当前不能判定为 B−C。

3. **领域块顺序造成明显的前缀效应**  
   C-51 只含算法/理论/语言/系统前4，所以语言前端主导；C-71 加入网络前9，网络/系统头部出现；C-91 加入数据库和部分 AI，出现多簇；C-111 加入完整 AI 和 SWE，AI 退出、SWE 进入。  
   不能把这条序列直接当作“规模轨迹”，它同时是“领域加入顺序”的序列。

4. **systems 是最稳定的 C 领域，但成员会重排**  
   数量稳定在 11 左右，但 `操作系统`、`分页` 在 C-111 退出，`调度算法`、`中断` 进入；`进程/线程/系统调用/并行` 支持度大幅下沉。  
   说明 systems 内部存在“总括概念让位于机制概念”的趋势。

5. **networks 在最大前缀下成为最突出的角色纯区域**  
   C-111 网络块 9/10 进入 C，前五全是网络概念。`HTTP协议` 是唯一非 C 网络边界。  
   实际意义：协议栈中的数据包、TCP/IP、路由、分布式系统、一致性协议等在当前事件结构下具有很强的局部功能一致性。

6. **algorithms 的持续缺席是最值得注意的负面信号**  
   它是最早、最大的领域块，但四组 C 均为 0。  
   在 C 口径下，算法概念更像“通用方法/跨领域工具”，不是角色纯单概念原子。  
   但这不等于算法无结构；需要 B 方法结果才能判断它们是否属于 B−C 的角色混合部分。

7. **C-111 的结构最“基础设施化”**  
   C-111 由 networks + systems + SWE + 少量 databases 组成；languages、theory、AI 全退出。  
   在 config_B 这个 CS 单领域概念集中，C 方法在最大前缀下更偏向“协议栈/OS 机制/工程实践”这类模块化、功能单一的基础设施概念，而不是算法、理论、语言范式或 AI 大模型概念。

## 8. 结论与注意事项

**一句话总结**：  
在 config_B 和方法 C 下，四组数据共同显示：C 方法提取的是**当前概念集和事件结构下的角色纯单概念功能原子**；这些原子随领域块加入顺序发生显著重排，早期偏语言/理论/系统核心，中期转向网络/系统，后期转向网络/系统/软件工程基础设施，而 algorithms 始终缺席、AI 只在部分前缀出现、languages/theory 在最大前缀退出。这个序列主要反映 **C 角色纯筛选 + config_B 领域块顺序 + 事件数变化** 的共同作用，不能直接当作纯规模轨迹，也不能在没有 B 方法结果时判定 B−C 或底/顶/中间元素。

后续若接入 B 方法，优先对照：
- `类型推断/闭包`、`HTTP协议`、`代码重构`、`SQL/索引`、`调度算法/中断` 这些高频非 C 或跨锚点变化的边界枢纽；
- `algorithms` 全缺席是否在 B 中表现为角色混合；
- `进程/线程/并发` 四方交集成员在 B−C 中的角色混合程度。

## 1. 现实意义：C 方法在 config_B 下抓到了什么“工程实体”

### 1.1 它抓的是“模块化功能单元”，不是“学科代表”

四组数据最一致的特征是：C 集合**不按领域比例出现**。

| 领域 | 前缀内概念数 | 四组 C 命中 |
|---|---:|---|
| algorithms | 22 | **0 / 0 / 0 / 0** |
| languages | 15 | 12 / 11 / 0 / 0 |
| systems | 15 | 4 / 11 / 11 / 11 |
| networks | 10 | 未含 / 2 / 5 / **9** |
| AI | 20 | 未含 / 未含 / 4 / **0** |
| SWE | 9 | 未含 / 未含 / 未含 / **6** |

现实解读：

- **algorithms 全缺席**：排序、查找、动态规划、贪心、分治、递归、迭代这些概念在 CS 工程里当然重要，但它们是**跨模块的通用方法**，不是某个局部模块的“功能专才”。C 方法要的是“在压缩事件里角色一致”的单元，算法概念往往在不同语境里以不同身份出现（排序算法既是算法又是数据结构操作，递归既是算法又是语言机制），所以角色混合。
- **languages 先高后零**：早期前缀里语言/编译概念是“前端流程专才”（词法→语法→语义→类型），角色很纯；但网络、数据库、AI、SWE 加入后，语言概念不再是事件结构的主轴，退出 C。
- **systems 稳定 11**：OS 机制（虚拟内存、调度、死锁、缓存、中断、系统调用）是典型的**模块化功能单元**，每个都有明确职责边界。
- **networks 到 C-111 覆盖 9/10**：协议栈本身就是分层模块化设计的典范，数据包、TCP/IP、路由、一致性协议各自职责清楚，C 方法几乎全部捕获。
- **SWE 6/9**：版本控制、设计模式、单元测试、敏捷开发、集成测试、需求分析——工程实践里的“可独立命名的活动单元”。

**工程含义**：C 方法在 config_B 下近似于一个**“功能专才检测器”**——它偏向那些在事件结构里反复以同一角色出现、职责边界清晰的模块化实体；对通用方法（algorithms）、桥接接口（类型推断/闭包/HTTP协议/SQL/索引/代码重构）、总括概念（操作系统）则不给 C 标签。

- `调度算法`、`中断` 在 C-91 是非 C，C-111 进入 C——说明“角色纯”不是固有属性，而是**随概念集和事件结构变化**的。

## 2. 哲学意义：对应交接文档的框架

交接文档给出的核心哲学坐标是：

- **C/B = 稳定单元里角色纯的占比 = 专才型原子 / 所有原子**
- **角色纯 ⇔ 语境独立 ⇔ 本质主义**
- **角色混合 ⇔ 语境依赖 ⇔ 关系主义**
- **“不动” ≠ “角色纯”；“不动” = 被所有概念调用 = 角色混合**
- **底元素 / 顶元素 / 中间元素需要 B 的 Lattice 位置，不能凭 C 单独判定**

在只有 C、没有 B 的情况下，能说的和不能说的要分清。

### 2.1 能说的：C 集合是“本质主义候选池”，不是“本质主义证明”

C 方法按角色一致性筛选，所以 C 集合里的成员是**“在当前前缀下表现为语境独立”的候选**。  
例如：

- `虚拟内存` 在 C-71/91/111 连续出现，boundary 始终是 OS 机制（中断、调度算法、死锁、并发、缓存、内存管理），角色高度集中 → 本质主义候选。
- `数据包` 在 C-111 成为 support 第一，boundary 是 IP/TCP/HTTP/路由/分布式系统，全部是网络协议栈内部 → 本质主义候选。
- `类型推断`、`闭包` 在 C-51/71 高频作为 boundary 但从未进入 C → 关系主义候选（语境依赖、桥接角色）。
- `调度算法`、`中断` 在 C-91 是非 C，C-111 进入 C → **同一概念在不同前缀下从关系主义候选转成本质主义候选**，说明“本质/关系”不是固有属性，而是相对于概念集和事件结构的。

**哲学含义**：这支持交接文档的修正——“稳定 ≠ 角色纯”。C 方法抓到的是**局部语境下的角色纯**，不是柏拉图式的本质。

### 2.2 能说的：“不动”在 config_B 中确实不等于“角色纯”

交接文档 §2.5 说：数学基础概念“不动”是因为被所有概念调用，角色混合，C/B 低。  
在 config_B 中可以看到类似结构：

- `类型推断`、`闭包` 在 C-51/71 被大量语言概念引用（高频 boundary），但不在 C → “被调用多”但“角色不纯”。
- `HTTP协议` 在 C-111 是唯一非 C 网络边界，被路由、数据包、TCP 等引用，但自身不在 C → 应用层接口，跨多个协议语境。
- `代码重构`、`SQL`、`索引` 在 C-111 是高频非 C 边界 → 跨实践/跨查询语境的通用操作。

**哲学含义**：config_B 的数据支持“高频 ≠ 角色纯”。一个概念被越多概念引用，越可能承担多种语境角色，越不容易通过 C 的角色一致性筛选。这与交接文档“不动 = 被所有概念调用 = 角色混合”的修正方向一致。

### 2.3 不能说的：底/顶/中间元素、B−C、C/B、轨迹形状

必须明确：

- 四组 C 结果全部是 **size-1 单概念 fixpoint**，`phi=null`。没有复合结构，就没有“内部平均/外部平均”的压缩势。
- 没有 B 方法结果，就**不能算 C/B**，**不能做 B−C**，**不能判定底元素/顶元素/中间元素**（那需要 B 的 Lattice 下界/上界位置）。
- 四个 scale 的序列同时受**领域块加入顺序**和 **n_events 变化**影响，不能直接当作“轨迹形状”（单调升/U 型/n 型）的证据。

所以哲学上能说的是：**C 方法在 config_B 下提供了一个“角色纯候选池”**，它让我们看到哪些概念在当前前缀下表现为语境独立；但不能说这些概念就是“本质”，也不能说非 C 概念就是“关系”。真正的本质/关系判定需要 B−C 对照。

### 2.4 “毛边”与 size-1 的限制

交接文档说“不动点本身没有毛边（boundary 大但 logic 弱），连接后产生新毛边”。  
在 config_B 的 C 数据中：

- 每个 fixpoint 是单概念，它的“毛边”只体现在 `boundary/logic/energy` 三字段上，没有复合结构的内部/外部对比（`phi=null`）。
- 所以当前数据的“毛边”是**单概念的外部边界**，不是不动点之间的耦合毛边。
- 这也解释了为什么 C-111 出现多个 boundary=2 的小节点（版本控制、单元测试、敏捷开发、套接字、需求分析）：它们的“毛边”很窄，局部角色纯但结构位置边缘。

**哲学含义**：size-1 C 结果是“原子级角色纯”，不是“复合概念群的压缩”。要谈毛边和降级机制，需要 G3 或至少 size≥2 的 fixpoint，当前数据不具备。

## 3. 随机抽样合理性检验：`虚拟内存`（C-71/91/111）与 `数据包`（C-91/111）

我抽两个跨锚点有变化的核心来检验：`虚拟内存`（systems 稳定成员）和 `数据包`（C-111 头部）。

### 3.1 `虚拟内存` 的结构数据

| scale | support/count | boundary（logic） | energy |
|---|---|---|---|
| C-71 | 0.231 / 122 | 死锁0.541、中断0.738、操作系统0.705、线程0.664、并发0.615、并行0.516、调度算法0.631 | 中断90、并发75、并行63、操作系统86、死锁66、线程81、调度算法77 |
| C-91 | 0.255 / 100 | 中断0.640、进程0.790、线程0.810、调度算法0.800 | 中断64、线程81、调度算法80、进程79 |
| C-111 | 0.198 / 49 | 中断0.612、内存管理0.694、并发0.816、死锁0.878、缓存0.592、调度算法1.000 | 中断30、内存管理34、并发40、死锁43、缓存29、调度算法49 |

**合理性检验**：

1. **角色一致性**：三次出现中，boundary 始终围绕 OS 内存/调度/并发机制（中断、调度算法、死锁、并发、缓存、内存管理），没有跨到网络、数据库、语言。这符合 C 的“角色纯”定义——虚拟内存在事件里始终作为“内存抽象机制”出现，不兼任其他角色。
2. **boundary 收窄再扩展**：C-71 含 `操作系统`、`并行` 这类较宽概念；C-91 收窄到 `进程/线程/调度算法`；C-111 又扩展到 `死锁/缓存/内存管理`。这说明它的“功能语境”在随概念集变化：从“OS 总括下的内存”变成“内存-调度-并发-缓存机制簇中的内存”。**角色纯不等于 boundary 固定**。
3. **logic 强度合理**：C-111 中 `虚拟内存→调度算法=1.0`、`→死锁=0.878`、`→并发=0.816`，都是强逻辑边；`→缓存=0.592` 较弱。这与工程直觉一致：虚拟内存与调度/死锁强耦合，与缓存是间接关系（通过内存管理）。
4. **energy 尺度合理**：C-111 energy 整体在 29–49，低于 C-71 的 63–90。这与 n_events 从 529 降到 247 一致，不是结构突变。
5. **不支持过度解读**：`phi=null`，size-1，不能判定它是底元素还是中间元素。它在 C 中稳定，只能说明“角色纯候选稳定”，不能说明“Lattice 位置稳定”。

**哲学对应**：虚拟内存是“本质主义候选”的典型——跨三个锚点角色一致。但它的 boundary 随前缀变化，说明“本质”是相对于概念集的，不是绝对的。这正好落在交接文档“角色纯 ⇔ 语境独立”的框架内，同时提醒“语境独立”是局部判断。

### 3.2 `数据包` 的结构数据

| scale | support/count | boundary（logic） | energy |
|---|---|---|---|
| C-91 | 0.168 / 66 | 网络拓扑0.833、一致性协议0.864、IP协议0.864、套接字0.879、路由0.621、计算机网络0.879 | IP57、一致性协议57、套接字58、网络拓扑55、计算机网络58、路由41 |
| C-111 | 0.401 / 99 | IP协议0.758、分布式系统0.788、路由0.636、HTTP协议0.535、TCP协议0.636 | HTTP53、IP75、TCP63、分布式系统78、路由63 |

**合理性检验**：

1. **角色一致性**：两次出现 boundary 全部是网络协议栈概念，没有跨到 OS、数据库、AI。符合“网络数据单元”的角色纯。
2. **boundary 重构**：C-91 的 boundary 偏“拓扑/套接字/计算机网络”，C-111 转向“IP/TCP/HTTP/分布式系统”。这与 config_B 前缀有关：C-91 时网络块刚完整加入，C-111 时网络概念已与系统/分布式系统充分交互。**同一个角色纯概念，其边界会随概念集扩张而重组**。
3. **logic 强度合理**：C-111 中 `数据包→分布式系统=0.788`、`→IP协议=0.758` 强；`→HTTP协议=0.535` 弱。工程直觉一致：数据包是 IP 层单元，与 HTTP 是间接关系（HTTP 在 TCP 之上）。
4. **support 第一的合理性**：C-111 中数据包 count=99，support=0.401（n_events=247）。它是网络块中 support 最高的 C 成员，boundary 覆盖 IP/TCP/HTTP/路由/分布式系统，说明它在事件结构里是最常被引用的网络单元。**但注意**：它在 C-71 不是 C，C-91 才进入，C-111 才成为第一。这说明“support 第一”是前缀效应，不是固有基础性。
5. **不支持过度解读**：不能因为数据包 support 第一就说它是“网络协议栈的底元素”。底元素需要 B 的 Lattice 下界信息（无频繁真子集），当前没有。

**哲学对应**：数据包是“本质主义候选”，但它的“不动”（C-111 support 第一）是**在完整网络块加入后才出现的**，不是“被所有概念永远调用”的那种不动。这恰好支持交接文档的修正：**“不动”要分清是“角色混合型不动”还是“角色纯型不动”**。数据包在 C-111 是角色纯型不动（C 保留 + 高支持），而 `类型推断/闭包` 在 C-51/71 是角色混合型不动（高频 boundary 但非 C）。两者不能混为一谈。

### 3.3 检验结论

- 抽样的两个概念在结构上**自洽**：boundary 领域集中、logic 强度分层合理、energy 尺度与 n_events 一致。
- 它们的 C 保留**不是随机噪声**：跨锚点 boundary 始终围绕同一功能域，符合 C 的角色纯定义。
- 但它们的 **support 排名和 boundary 组成会随前缀变化**，说明“角色纯候选”是局部判断，不是绝对本质。
- 当前数据**不支持**把它们判定为底/顶/中间元素，也不支持算 C/B 或 B−C。

## 4. 综合总结

**现实意义**：  
config_B 方法 C 在四个前缀下抓到的是一组**模块化功能专才**——OS 机制、网络协议栈、工程实践、部分数据库/语言/理论概念。它系统性地缺席 algorithms（通用方法）、过滤掉高频桥接接口（类型推断/闭包/HTTP协议/SQL/索引/代码重构），并在最大前缀下把网络协议栈推成最突出的角色纯区域。这个结果对工程有直接含义：**C 集合近似“职责边界清晰的模块清单”**，而不是“学科重要性排名”。

**哲学意义**：  
C 集合是**本质主义候选池**，不是本质主义证明。它支持交接文档的两个关键修正：

1. **稳定 ≠ 角色纯**：高频 boundary 但非 C 的概念（类型推断、闭包、HTTP协议、SQL、索引、代码重构）是关系主义候选；C 保留但 support 波动的概念（虚拟内存、数据包）是局部本质主义候选。
2. **“不动”要分型**：数据包在 C-111 的高支持是“角色纯型不动”，类型推断/闭包在 C-51/71 的高频是“角色混合型不动”，不能混同。

同时必须明确限制：当前全是 size-1、`phi=null`、无 B 结果，所以**不能算 C/B、不能做 B−C、不能判定底/顶/中间元素、不能宣称轨迹形状**。C 数据只能支持“角色纯候选池”和“边界枢纽迁移”层面的判断。

**抽样检验**：  
`虚拟内存` 和 `数据包` 的结构数据自洽——boundary 领域集中、logic 分层合理、energy 与事件数一致；它们跨锚点稳定进入 C 支持“角色纯候选”判断；但 boundary 重组和 support 变化说明这是局部判断，不是绝对本质。当前数据不足以做更进一步的 Lattice 或 B−C 判定。
